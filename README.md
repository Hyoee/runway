# RunWay — 서울 도심 마라톤 코스 최적화 (PuLP MILP + LLM 챗봇)

> **버스 승객 피해는 최소로, 코스는 단순하게.**
> 대회 기획자가 말로 조건을 바꾸면, 수리최적화(MILP) 솔버가 서울시 버스 승하차 공공데이터로
> 시민 피해가 가장 적은 42.195km 코스를 계산하고, LLM이 결과를 설명한다. **LLM은 의미를, 솔버는 숫자를.**

## 결과 요약 — 2026 JTBC 서울마라톤 코스(AS-IS) vs RunWay(TO-BE)

기준: **일요일(대회일) 수요**, **출발 07:30**(대회 책자 p17), 승객 지표 = **정류장이 코스에 들어가 통제 시간 동안 버스를 못 타는 승객**.
AS-IS = **2026 JTBC 서울마라톤 공식 풀코스**(대회 책자 p28~29 경유지, `data/asis_2026_official.json`에 고정).

| KPI | AS-IS | **TO-BE** | 변화 |
|---|---:|---:|---:|
| **못 타는 승객 (명/일요일)** | 28,417 | **13,723** | **−52%** |
| km당 못 타는 승객 (명/km) | 658 | 323 | −51% |
| 통제되는 정류장 (곳) | 157 | 220 | +40% |
| 영향 받는 버스 노선 (개) | 156 | 131 | −16% |
| 방향 전환 45° 이상 (회) | 21 | 10 | −52% |
| 급한 방향 전환 100° 이상 (회) | 6 | 2 | −67% |
| 통제 필요 교차로 (곳) | 57 | 55 | −4% |
| 도로 통제 부담 (km×시간) | 91 | 95 | +4% |
| 10시 이후까지 막히는 도로 (km) | 25.4 | 25.8 | +2% |
| 코스 길이 (km, 공인 42.195) | 43.163 | 42.459 | −2% |

조건별 TO-BE (미리 계산 — 앱·챗봇이 즉시 답함, 못 타는 승객): 출발 07:00 **14,116** · 08:00 **13,252** · 09:00 **12,364**

**AS-IS의 문제점 (모델 검사)**: 반환 왕복(청계천 비우당교·학여울·둔촌사거리) 등 **회귀 구간 약 15km**, 같은 동네 재방문 38곳,
공인 거리 범위 초과(모델상 43.2km), 건국대병원 앞(응급 동선) 통과,
광화문·종로·동대문 등 **붐비는 도심 정류장**을 지나감 — 06~14시 승차 1,000명 이상 정류장이 AS-IS 37곳, TO-BE 3곳.
TO-BE는 통제 정류장이 더 많지만 정류장당 이용객 중앙값이 428명 → 174명으로, **사람이 적은 정류장**을 골라 지나간다.

**TO-BE 코스 규칙 (하드 제약)**: 출발(광화문)·도착(올림픽공원) 고정, 42.195~42.6km, 교차로 1회 통과,
**회귀 금지**(반환 왕복·반대 차로·1km 안에서 반대 방향으로 되돌아오기), **재방문 금지**(코스상 2km 넘게 떨어진 두 지점이 300m 안에 오지 않음),
금지 구간 회피, 버스 정류장 데이터가 있는 영역 안의 도로만.

> **결과의 안정성**: 솔버의 최적성은 'LP 완화가 고른 후보 회랑 안에서 gap 이내'이고, 승객 피해를 3km 구간대 평균으로 근사한다.
> 그래서 찾은 코스를 모두 저장해 두고 조건마다 서로 대입해, **화면 KPI와 같은 정밀 평가(10m 단위)로 계산한 목적함수**가
> 더 작을 때만 교체한다 — 다시 풀어도 발표 숫자가 나빠지지 않는다.

## 종목별 결과 (풀코스 / 하프 / 10K)

같은 규칙(회귀·재방문 금지, 금지 구간 회피, 데이터 영역 안)과 같은 목적(못 타는 승객 + 코스 단순성)으로 종목마다 풀었다.
거리 허용 오차는 풀코스 비율(42,600 / 42,195)을 종목 거리에 비례 적용. 랜드마크(롯데타워) 조건은 어느 종목에도 없다.

| 종목 | 출발 → 도착 | AS-IS 못 타는 승객 | TO-BE 못 타는 승객 | 변화 | TO-BE 코스 길이 | 영향 노선 (AS-IS → TO-BE) |
|---|---|---:|---:|---:|---:|---:|
| 풀코스 | 광화문광장 → 올림픽공원, 07:30 | 28,417 | **13,723** | **−52%** | 42.459km | 156 → 131 |
| 하프 | 광화문광장 → 올림픽공원, 07:30 | 해당 없음 | **8,205** | 해당 없음 | 21.274km | 해당 없음 → 90 |
| 10K | 상암 월드컵공원 → 여의도공원, 07:30 | 7,383 | **6,238** | **−16%** | 10.086km | 67 → 73 |

- **10K AS-IS**: 2026 JTBC 서울마라톤 대회 책자 p34 「10K 코스 안내」 (2026년 공개 코스 기준) — 상암월드컵공원 앞 → 합정역 → 양화대교 남단 → 여의2교 → 여의하류IC → KBS 앞 교차로 → 마포대교 남단 → 여의도공원.
  경유지를 도로망 최단 경로로 이어 모델상 10.445km(공식 10km 대비 +0.4km), 여의하류IC 머리핀 구간이 회귀(약 2.7km)로 잡힌다. `data/asis_10k_2026_official.json`에 고정.
  10K는 못 타는 승객이 16% 줄지만 통제 정류장(46 → 55)·영향 노선(67 → 73)은 늘어난다 — 목적이 '못 타는 승객'이라 한산한 정류장을 더 지나가는 선택.
- **하프**: 공식 하프 코스가 없어 AS-IS 비교를 하지 않는다(화면·챗봇 모두). 출발·도착은 풀코스와 같은 기본값, 컷오프 3시간 가정.
- **10K 도로망**: 기존 `osm_roads.json`이 경도 126.93 동쪽만 담고 있어, 서울 서부 도로를 `scripts/fetch_osm_west.py`로 받아 `data/osm_roads_west.json`에 따로 둔다
  (풀코스 도로망·결과는 그대로 — 테스트로 확인). 통제 해제는 책자 p17의 10K 종료 10:30에 맞춰 컷오프 2.5시간 + 해제 여유 30분.

## 무엇을 최소화하나 — 정류장이 코스에 들어가 버스를 못 타는 승객

```
목적함수 = 못 타는 승객 + 꺾임·되돌아오기·재방문 벌점 + 미세 거리비용
```

- **못 타는 승객**: 버스 정류장이 마라톤 코스 안에 들어가면, 그 도로가 통제되는 동안 그 정류장에서 버스를 탈 수 없다.
  그 시간 동안 그 정류장에서 타려던 승객 수(일요일 실측 수요)를 더한다.
- **통제 시간은 위치마다 다르다**: 07:30 출발, 출발점에서 d km 지점은 [선두 도착 − 15분, 후미 통과 + 30분] 동안만 막힌다
  (후미 5시간 컷오프 → 올림픽공원 13:00 해제 = 공식 풀코스 종료 13:00과 일치).
  그래서 같은 도로라도 코스의 몇 km에 놓이느냐에 따라 못 타는 승객이 달라지고, MILP는 이를 3km 구간대별 비용으로 반영한다.
- **코스 단순성 벌점**: 방향 전환 1회 = 승객 1,000명 상당(100° 이상 2,000, 150° 이상 5,000), 되돌아오기 1m = 3, 같은 동네 재방문 1m = 2.
- **정류장 수·노선 수는 KPI로만 본다**: 개수라서 크기를 반영하지 못한다. 정류장마다 이용객이 달라, 정류장이 더 많아도 못 타는 승객은 더 적을 수 있다.

### 대회일 수요 — 사용일자로 판별
원자료(노선×정류장×일별 승하차, 2026-10)의 사용일자로 날의 유형을 나눈다 → `data/daytype_calendar_202610.csv`

| 유형 | 일수 | 하루 평균 승차 |
|---|---:|---:|
| 평일 | 19 | 546만 |
| 토요일 | 5 | 420만 |
| **일요일 (대회일 유형)** | **4** | **323만** |
| 휴일 (10/5 개천절 대체공휴일, 10/9 한글날) | 2 | 358만 |

휴일은 날짜를 외워 넣지 않고 "평일인데 승차가 평일 중앙값의 80% 미만이고 운행 노선이 주말 수준"이라는 규칙으로 데이터에서 찾았다.
마라톤은 일요일 오전이므로 **일요일 4일 평균**을 쓴다(토·일 평균을 쓰면 토요일 수요 때문에 피해가 25~30% 과대 추정된다).

## 구조

```
runway/            최적화 엔진 (LLM 없이 동작, 테스트됨)
  params.py        제약 카드 = 검증 가능한 스키마 (LLM이 채우는 값)
  network.py       도로 그래프·정류장 연결·형상 특징 (캐시)
  events.py        종목 프리셋 (풀코스·하프·10K: 거리·출발·도착·컷오프·영역·도로망·AS-IS 파일)
  scenario.py      조건별 값: 통제 시간 피해표, 금지 구간, 출발·도착 검증
  model.py         MILP 수식 (목적함수 5-4, 제약식 5-5)
  solve.py         LP 완화 → 후보 회랑 → MILP
  evaluate.py      KPI·제약 검사·목적함수 재계산
  engine.py        서비스 진입점: 결과 캐시, 더 좋은 해만 교체
  places.py        장소 이름 → 좌표 (버스정류소 위치 데이터에서만 — LLM이 좌표를 지어내지 않음)
agent/             Claude 도구 계층 (Tool Runner) + 숫자 검증
app.py             Streamlit: 조건 카드 · 지도 · KPI · 채팅
scenarios/         미리 계산한 결과 (즉시 응답용)
scenarios_v1/      노트북 목적식(v1)으로 구한 결과 — 새 계산의 출발 후보
scripts/precompute.py          대표 시나리오 사전 계산
scripts/build_route_data.py    원자료(144MB) → 노선×정류장 요약(2.2MB) + 날짜 유형 판별
tests/             노트북 결과 재현(v1) + MILP 식 = 재계산(v1·v3) + 데이터 검증
RunWay_코스최적화_StepByStep_PuLP.ipynb   수식·과정 설명 노트북
```

## 로컬 실행

```bash
pip install -r requirements.txt
pytest -q                                   # 회귀 테스트 (~40초)
streamlit run app.py                        # http://localhost:8501
```
채팅을 쓰려면 Claude API 키를 환경변수로: PowerShell `$env:ANTHROPIC_API_KEY="..."` (키는 커밋하지 않는다).
키가 없어도 사이드바 조건 카드로 모든 계산 기능을 쓸 수 있다.

## 배포 (Streamlit Community Cloud)

1. https://share.streamlit.io → GitHub 로그인 → **Create app**
2. Repository `Hyoee/runway`, Branch `main`, Main file `app.py`
3. **Advanced settings** → Python **3.11** (테스트한 버전), **Secrets**에:
   ```toml
   ANTHROPIC_API_KEY = "sk-ant-..."
   ```
4. Deploy → 첫 실행 때 도로망을 만드는 데 20~30초.
5. Anthropic 콘솔에서 **월 사용 한도(spend limit)** 를 걸어 둔다 — 공개 URL은 누구나 채팅할 수 있다.

미리 계산된 시나리오는 즉시 뜨고, 새 조건은 서버에서 최대 2분(시간 제한 120초, gap 2%) 풀이한다.
