# AI 활용 내역 (홈페이지 입력용 초안)

> 제출 규칙: "홈페이지 「AI 활용내역」: AI와 팀의 역할 및 검증 과정을 작성". 팀의 실제 작업 방식에 맞게 수정하세요.

## 1. 서비스 안의 AI (제품 기능)
- **모델**: Anthropic Claude Opus 5.5 (Claude API), Python SDK의 Tool Runner로 도구 6종 호출
- **역할**: 사용자 문장을 조건(제약 카드)으로 변환, 장소 이름 해석(정류소 데이터 검색), 도구 호출 순서 결정, 결과 설명
- **AI가 하지 않는 일**: 코스·거리·승객 수 등 숫자 생성 — 수리최적화 엔진(PuLP + HiGHS)만 계산
- **검증 장치**: 조건 값 스키마 검증(Pydantic), 장소는 데이터에서만 검색·모호하면 사용자 선택, 답변 속 숫자를 도구 결과와 자동 대조해 근거 없는 숫자 경고, 해가 없으면 완화 후보 제시 후 사용자 승인, 안전 분류기 거절 시 서버 측 대체 모델

## 2. 개발 과정의 AI (개발 도구)
- **도구**: Claude Code (Anthropic)
- **AI가 한 일**: 노트북 코드를 패키지로 구조화, 최적화 제약식(회귀·재방문 금지 등) 구현, Streamlit 앱·에이전트 코드 작성, 데이터 분석(사용일자 판별 등), 테스트 작성, 소개서 빌드 스크립트 작성
- **팀이 한 일**: [작성] 문제 정의, 목표·평가 기준 결정(예: 승객 지표를 '못 타는 승객'으로 정함, 회귀 금지, 롯데타워 조건 제외), 공식 AS-IS 코스 확인, 결과 검토와 수정 지시
- **검증 과정**
  - 노트북 결과 재현 테스트(도로망 구간 수, AS-IS·TO-BE KPI, LP 하한이 노트북과 일치)
  - MILP 목적함수 = 독립 재계산 함수 일치 테스트(경로 하나뿐인 회랑에서 비교)
  - 휴일 판별·노선 이용객 합계·공식 AS-IS 고정 테스트
  - 사람이 지도를 보고 회귀·고리 문제를 찾아 제약을 추가하는 반복 검토(데이터 없는 외곽 도로 왜곡 발견·수정 포함)
  - 배포본 브라우저 콘솔 오류 점검(Playwright)
